# 片段處理、核對與匯出

## 處理與恢復

音訊先轉為單聲道 PCM，依取樣點建立連續且涵蓋全檔的片段清單。每份清單保存音檔 SHA-256、辨識設定指紋、片段起訖、辨識／對齊狀態、耗時與診斷；續跑前重新確認音檔、設定及完整範圍。

預設採低音量切點，Qwen 最大片段為 60 秒，Whisper 為 300 秒。Qwen 設定上限為需要字幕時 180 秒、不需要字幕時 1,200 秒，遵循套件的輸入限制。`chunk_seconds` 與 `chunk_strategy` 可用於比較其他長度及固定切段；這些預設是資源管理選擇，並未證明對所有日文、日中交替或中英內容最佳。

辨識與對齊分兩個階段：先逐段保存原始辨識，再逐段處理字幕時間。Qwen 在需要對齊時才載入對齊模型；載入或對齊失敗仍保留原始辨識。重試字幕時間使用已保存文字及可靠對齊，不要求全檔重新辨識。Whisper 的原生時間資訊隨辨識取得。

每段結果以暫存檔、同步寫入及原子更名保存。單段辨識失敗不阻止其餘片段；全部辨識失敗會標示工作失敗，同時保留缺口供核對。取消採合作方式：等待目前模型呼叫結束並保存後停止，不能立即中斷正在執行的 GPU 呼叫。取消時會由已保存片段產生可核對的部分結果，尚未處理的範圍明確留白。工作程序意外退出後，下次啟動會沿用檢查點。

同一後端可重用模型；切換後端時工作程序先退出，由新的程序接手下一份工作，避免不同 GPU 執行環境的殘留記憶體互相影響。評測矩陣也使用各策略獨立程序，記錄程序耗時與失敗。

## 文字來源與字幕驗收

- `Transcript.raw_text` 及片段 `raw_text` 保留辨識原文。`text` 是共用顯示稿，全文、段落、講者逐字稿與匯出均使用此來源。
- 繁中轉換對完整顯示稿執行一次，再將字串位置映射回段落及字詞。詞彙長度改變不會被解釋為新增的聲學時間。包含日文的稿件保留原字形，不任意轉換日本漢字。
- 沒有可靠時間的段落保留文字及原音範圍，`alignment` 標示不可用；這個範圍僅供回聽，不冒充精確字幕或可靠講者歸屬。
- 最終字幕另外檢查有限且非負的時間、毫秒格式後的正長度、至少 100 毫秒、順序／重疊、音訊範圍、空文字、可見字元、控制字元、段落大小及過高閱讀速度。每秒超過 25 字會提示，超過 60 字拒絕；這是保守的完整性界線，不是各語言的閱讀品質評分。
- `metadata.subtitles` 列出通過數、拒絕數、文字覆蓋率、缺口及原因。SRT／VTT 僅包含通過的段落；TXT／JSON 保留未對齊文字。全無有效字幕時不提供字幕檔，不補造時間。

`diagnostics.issues` 區分辨識失敗、確認的數位靜音、疑似漏辨／重複／截斷、低信心及對齊失敗。音量低或沒有辨識文字本身不能證明沒有語音，不能把疑似診斷當作人工驗證。Whisper 保留可取得的機率、壓縮比、token 與 VAD 資訊；Qwen 保留語言、原始回傳及套件有提供的生成診斷。未提供停止原因的套件版本會明確標記無法取得，不推測生成是否已截斷。

## 核對與修正

現有前端可播放原音、點擊段落時間回聽、查看辨識原文、修正文字、重試某段辨識或 Qwen 字幕時間，以及停止／繼續工作。進度中的「片段」是處理音訊範圍；逐字稿中的「段落」是閱讀／字幕單位，一個片段可能包含多個段落。

修正保留原始文字，並清除已不對應新文字的字級時間。有效的段落時間可繼續使用，但新文字仍必須通過字幕驗收。修正未對齊的文字不會自動產生可靠字幕時間。

每次儲存都建立新的不可變匯出版本，最後一次原子更新發布目前版本與修正紀錄。所有下載連結綁定同一版本；同時編輯或使用過期版本儲存時回報衝突，保留編輯內容供重新核對。重新辨識選定原音片段會取代該範圍的文字修正。只重試對齊時，舊修正必須與原始文字及段落身分仍相符才會套用；無法對應的修正保留並顯示待核對提示。

## API

既有建立、上傳及下載介面保留；新增以下端點：

| 方法 | 路徑 | 用途 |
| --- | --- | --- |
| GET | `/api/jobs/{id}/chunks` | 處理片段、各階段狀態及進度 |
| GET | `/api/jobs/{id}/audio` | 原音播放，支援 HTTP Range |
| POST | `/api/jobs/{id}/cancel` | 要求停止並保留已完成片段 |
| POST | `/api/jobs/{id}/resume` | 續跑或指定片段重試 |
| PATCH | `/api/jobs/{id}/segments/{segment_id}` | 儲存文字修正並更新全部匯出 |

```json
{"chunk_ids":["000002"],"stage":"alignment","revision":"目前結果的版本字串"}
```

`stage` 可為 `asr`、`alignment` 或 `failed`；省略 `chunk_ids` 並使用 `failed` 會續跑未完成或失敗範圍。處理中不能同時提交修正或重試。修正請求為 `{"text":"修正後文字","revision":"目前結果的版本字串"}`；版本可從 `transcript.metadata.revision` 取得。

新的輸入設定包括 `context`（背景）、`glossary`（詞庫）、`condition_on_previous_text`、`context_token_budget`、`glossary_token_budget`、`chunk_seconds` 及 `chunk_strategy`。Whisper 的背景及前文送入 `initial_prompt`，詞庫送入 `hotwords`；兩者不重複注入同一份 context。Qwen 使用自身情境格式。各後端限制文字預算，優先使用模型 tokenizer，無法取得時以保守的 UTF-8 位元組上界估計，並保存截斷診斷。

## 檔案與評測

工作目錄包含 `audio.wav`、`chunks.json`、`chunks/{id}.asr.json`、`chunks/{id}.aligned.json`、`asr.json`、可選的 `diarization.json`、`revisions/{revision}/result.*` 及 `current.json`。舊版 `output/result.*` 仍可讀取；不自動搬移或修改既有結果。

可重複評測命令、人工參考格式、作者字幕的限制及真實模型比較見 [辨識品質紀錄](accuracy.md)。跨模型錯誤互補是評測項目；目前沒有自動第二模型辨識或自動校正，以免把模型分歧誤當成正確答案。
