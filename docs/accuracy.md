# 辨識品質紀錄

本次重點為純日文、日中混合課程，以及繁中／中英混合的專有名詞。改善分成「修復輸出損壞」與「改善模型輸入」，兩者不能混為整體辨識正確率。

## 已實作

- Qwen 時間對齊保留 ASR 原文的字形、標點、金額與空白；對齊器的清洗字串只用來對應原文，不能直接取代原文。
- 中文與英文混合字幕不任意插入空白；日文及含日文的混合稿不套用整篇繁體中文轉換。
- 無可靠對齊時保留原稿，不虛構整段字幕時間或把整篇文字指定給單一說話者。
- 提供專有名詞輸入，傳入實際辨識 backend；日中混合課程保持自動語言辨識，另外加入雙語課程情境。
- Qwen 補齊支援語言代碼；無時間戳的長音訊也使用套件既有切段能力，避免單次生成字數限制截掉後半段。
- 長音訊以可設定的低音量切點或固定長度切段；先完成並保存各段 ASR，再進入對齊，避免對齊模型占用記憶體影響後段辨識。可靠片段、未對齊缺口及各段錯誤均保留，對齊重試重用已保存的 ASR。
- faster-whisper 保留 beam search 與 VAD，情境、詞庫與前文分別管理 token 預算，不再把同一情境同時注入 `initial_prompt` 與 `hotwords`。切段與前文條件皆可設定，不能把固定短切段或關閉前文視為普遍最佳值。

目前另以 100 ms 視窗、−50 dBFS RMS 門檻記錄音訊活動；在可靠時間前後各保留 0.3 秒後，超過 1 秒的未涵蓋活動僅標為「可能漏辨」供回聽，音樂、噪音或時間偏差也可能觸發，不能當作已確認語音或漏句。

## 實測證據與限制

使用 [Google FLEURS](https://huggingface.co/datasets/google/fleurs) 的短日文與中文錄音，以及原資料提供的參考文字。音訊授權為 CC-BY-4.0。日中功能樣本由短日文與中文錄音加上短靜音串接而成，不是實際研習課錄音。

在同一個已快取的 Qwen3-ASR-1.7B 模型上，觀察到：

| 情境 | 原本行為 | 加入修正／相關情境提示後 |
| --- | --- | --- |
| 日文術語 | 將「敵対的環境コース」錯聽為「適体適環境コース」 | 輸入正確術語提示後可辨識為「敵対的環境コース」 |
| 日文後接中文 | 未提供課程情境時漏掉中文段落 | 日中課程情境下保留兩種語言 |
| 中文後接日文 | 未提供課程情境時也漏掉中文內容 | 日中課程情境下保留兩種語言 |
| 日文字形 | 繁中後處理會改動日文漢字，例如「体」 | 日文原稿字形保留 |
| 金額字串的對齊回歸 | `$1.50`、`$15.00` 會變成 `150`、`1500` | 字幕與語者逐字稿保留原始金額 |

金額檢查使用實際對齊器的文字前處理搭配假模型回傳，是確定性的輸出回歸測試。其餘辨識例使用真實模型與短公開音訊。

這些結果證明特定問題已修復，並顯示相關情境及詞彙提示對這些樣本有幫助。它們不是完整的 CER／WER 基準，不能推算整堂研習課的正確率；時間戳只有範圍、順序與內容一致性檢查，沒有人工逐字時間標註。加提示也可能改變標點，過多或不相關的提示可能造成其他誤辨。

另以兩支約 10 分 51 秒、19 分 35 秒的日文影片驗證完整流程。在 GPU 可用記憶體約 8 GiB 的環境，原先較長切段會記憶體不足；改為約 60 秒低音量切段與單段推論後，同一個 Qwen3-ASR-1.7B 模型完成兩支轉錄，分別產生 119 與 253 個字幕段落。TXT／SRT／VTT／JSON 均可下載，逐字內容完整對應輸出文字，時間順序及範圍檢查通過；未以人工校正稿計算辨識正確率。

下一步若要比較實際課程正確率，應使用有人工校正稿的日文、日中交替及問答片段，固定音檔、模型與設定，分別計算日文／中文的字元錯誤率、專有名詞命中率、漏段及語者歸屬錯誤。不能只看介面完成狀態或單一字幕範例。

## 可重複評測工具

`python -m echoscript.evaluation` 提供三個命令，不需另裝評測套件：

```bash
python -m echoscript.evaluation validate /path/to/manifest.json
python -m echoscript.evaluation run /path/to/manifest.json --output-dir /path/to/evaluation-run
python -m echoscript.evaluation score /path/to/manifest.json /path/to/hypotheses.json --output /path/to/report.json
```

`run` 依音檔與策略矩陣使用現有完整轉錄流程，逐次保存原始 ASR、最終顯示文字、選項、模型診斷、音檔 SHA-256、程式 SHA-256、套件版本及處理時間。多個策略各自使用新的子程序，避免原生 CUDA 資源影響下一個策略。重新執行會重用相同設定的已完成結果，未完成片段可重試，並在 `runtime.attempts` 累積每次耗時與總成本；設定或音檔改變時要求使用新的輸出目錄，避免混入舊結果。`--policy 策略代號` 可只執行一種策略。執行錯誤保留在結果中，不以空文字或假字幕取代。

矩陣使用 `JobOptions` 的實際選項；未知選項直接報錯。每個策略執行時另存對應程式雜湊的 source ZIP，供固定程式版本重跑。模型名稱之外，正式基準應指定固定 revision 的本機模型路徑。工具不會把套件版本或可變的模型名稱冒充為權重 revision。成本僅在提供 `cost_per_hour` 與 `currency` 時依實測時間估算；未提供時為 `null`，不代表免費。

以下是結構示例，文字與時間須換成經人工核對的資料，不能把示例當實測資料：

```json
{
  "schema_version": 1,
  "cases": [{
    "id": "lesson-ja-zh-01",
    "audio": "audio/lesson-ja-zh-01.wav",
    "sha256": "替換成音檔的 SHA-256",
    "languages": ["ja", "zh"],
    "corpus_type": "natural_code_switching",
    "reference": {
      "human_verified": true,
      "provenance": "參考稿來源、校對者與校對日期",
      "language": "ja,zh",
      "raw_text": "人工核對的原始逐字稿",
      "display_text": "人工核對的預期顯示稿",
      "terms": ["專有名詞"],
      "numbers": ["二零二六"],
      "utterances": [{"id": "u1", "text": "人工核對的原始逐字稿", "start": 0.5, "end": 4.2}]
    }
  }],
  "policies": [
    {"id": "qwen-energy-60", "options": {"asr_backend": "qwen", "chunk_seconds": 60, "chunk_strategy": "energy", "language": null, "context": "", "glossary": ""}},
    {"id": "qwen-energy-120", "options": {"asr_backend": "qwen", "chunk_seconds": 120, "chunk_strategy": "energy", "language": null, "context": "日中雙語課程，日本講師與台灣翻譯輪流說話。", "glossary": ""}},

    {"id": "whisper-no-history", "options": {"asr_backend": "faster-whisper", "asr_model": "large-v3-turbo", "chunk_seconds": 300, "condition_on_previous_text": false}}

```

比較切段長度時保持情境、詞庫及其他選項一致；比較上下文時保持切段一致。上例展示可設定維度，不是能直接歸因的完整實驗設計，也不表示 60 秒或關閉前文條件較好。以同一批自然日文、自然日中交替、中英混合片段進行成對比較，再按語言與內容類型分組；串接錄音必須另列，不能取代自然交替課程。

既有輸出可用以下 `hypotheses.json` 結構直接評分，路徑相對於此檔案；也可把 JSON 物件直接放入 `raw`、`display`：

```json
{"schema_version": 1, "runs": [{"case_id": "lesson-ja-zh-01", "policy_id": "qwen-energy-60", "raw": "job/asr.json", "display": "job/output/result.json", "options": {"zh_script": "tw"}, "provenance": "原始執行紀錄位置與版本"}]}
```

### 指標的意義與限制

- `asr`：人工原始稿與未轉換 ASR 的 CER／WER。CER 使用 NFC、忽略標點和空白並摺疊大小寫，不做繁簡或日文字形轉換；`cer_verbatim` 另計包含符號、標點及空白的錯誤，避免 `$1.50 → 150` 被正規化掩蓋。
- `postprocessing_on_reference`：把人工原始稿交給目前後處理，再與人工顯示稿比較，獨立驗證字形／詞彙轉換。它不把模型誤辨歸給後處理，也不宣稱涵蓋錯誤 ASR 與後處理的所有交互作用。須同時提供 `display_text` 及執行選項 `zh_script`，缺少時不計算。
- `final`：實際最終顯示稿對人工顯示稿的錯誤。ASR 與 final 的差值不能直接解釋成後處理錯誤；不同字形規範可能使兩者基準不同。
- `wer_whitespace`：僅以空白分詞，沒有日文／中文斷詞模型；日中評測以 CER 為主，不把這個 WER 宣稱為日文詞錯誤率。
- `numbers`／`terms`：保留小數點、貨幣符號及詞彙原貌的出現次數，另外支持人工列出的中文數字。這是精確字串核對，不是數字語意等價判斷。
- `utterances`：依最小編輯對齊估計漏句；一個人工句子至少 80% 字元被刪除時標為疑似漏辨。整句超額重現另標疑似重複；末尾刪除字元數另列。這些是可供核對的診斷，不能區分所有改寫、同音詞或口吃情形。
- `timestamp`：只有人工起訖標註及相符的模型字詞邊界才能計算誤差；缺字、未對齊或缺人工時間都明確標示。作者字幕的顯示時間不是人工逐字起訖標註，不能直接當逐字時間真值。
- `runtime`：包含模型載入的牆鐘秒數、音檔秒數與實時倍率；歷史資料須自行標明是否包含模型載入。成本取決於使用者提供的每小時費率，未量測 GPU 能耗或外部帳單。
- `complementarity`：同一人工片段中，兩種策略各自獨有與共有的參考字元錯誤，以及總編輯錯誤；不把兩個模型「有分歧」視為互補。這是知道答案才能得到的機會上限，不能證明自動挑選或校正有效，因此工具保持自動跨模型校正關閉。

`inference_integrity` 另外列出辨識是否完整及對齊狀態；OOM、對齊失敗或部分完成不能被解讀成一般辨識品質落差。模型互補比較會拒絕音檔雜湊不一致的配對；舊假設未記錄雜湊時，明示其音檔身分證據不足。`policy_processes` 保留子程序退出碼、總牆鐘時間與日誌位置，包含程序啟動、模型清理及評分等每次辨識時間之外的開銷。

缺少人工參考稿的案例會回報 `missing_human_reference`，矩陣缺跑項目列在 `missing_runs`。精確編輯距離為二次複雜度，單次比較限制 2,500 萬格；長課程應以人工標註的多個可重複片段評測，不以粗略字串比對冒充 CER。數值工具的單元測試全部為明確的合成文字案例，不計入真實模型品質證據。

作者上傳的字幕可指定 `source_kind: "author_subtitle"`、`human_verified: false`，並記錄字幕來源、原檔雜湊及前處理。這類結果標為 `scored_against_author_subtitle`／`author_subtitle_not_verbatim_audited`，衡量與作者字幕的差異，不宣稱是逐字校對後的識別準確率。字幕可能整理口語、使用另一套字形、包含非語音標籤或拼字錯誤；不能把字幕差異一概視為模型誤辨。

這批資料呈現不同取捨：Qwen 在 AI Agent 作者稿較接近參考，Whisper 在串接雙語、角色名及英文作者稿較接近參考；Whisper 60 秒在英文優於 30 秒，關閉前文在該英文樣本反而增加差異。日文術語句中，兩者同為 3 個字元錯誤，但最小編輯對齊定位在互不重疊的參考位置。這足以證明少量樣本存在錯誤互補機會，仍不能證明一個不看答案的選擇器能安全合併正確部分；自動跨模型校正保持關閉。

硬體為 RTX 5090 32 GiB，測試開始時其他既有程序占用約 25 GiB，未更動該程序。模型均使用本機快取，權重 revision 與套件版本保留在資料包。各策略處理 6 份素材的累積時間為 22.55–28.30 秒，包含模型載入；8 個隔離策略加上程序啟動、評分及清理的總牆鐘時間為 246.16 秒。未提供費率，所以金額成本保留 `null`。正式效能比較仍需固定外部 GPU 負載並重複量測。

執行期間其他 API 與評測程式仍有修改，故整個 Python 套件記錄了 6 個 source SHA-256；只成功保留最後一組策略的完全相符快照，其餘歷史雜湊缺少完整快照的限制記錄於 `environment.json`，沒有冒稱與最終版本相同。資料包另存目前可重跑的程式基準；之後的 runner 已會在策略開始時自動保存對應 source ZIP。

48 次推論之後，另加入「有音訊能量但未被可靠時間涵蓋」的片段提示。使用既有日文接中文的錄音與 Qwen 快取、禁止載入模型進行 CPU 回歸，於中文所在的 15.1–16.5 與 17.0–18.3 秒提出疑似缺口，也在日文時間邊界提出其他候選。這是供原音核對的能量提示，音樂、雜訊或時間邊界偏差也可能觸發；不宣稱已確定漏句。證據另存資料包 `diagnostics-followup/`，原始 48 次假設與辨識指標未改寫。

仍缺自然日中交替的原語言人工稿、作者稿逐句回聽複核、人工字詞時間與更大的獨立測試集。不能以本表推定整堂課的正確率、最佳切段設定或通用校正規則。
